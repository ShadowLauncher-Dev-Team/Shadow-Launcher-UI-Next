> 参考稿：`shots/proto-d.png`（推荐方案 D · 全幅）、`shots/proto-d-800.png`

## 1. 首屏信息准入标准（v2 新增，优先级最高）

> **一个元素能留在首屏，唯一理由是：它能改变用户下一步的动作。**
> 说不出它改变哪个决定，就删掉它。

按这条标准逐条判掉的东西（v1 里全部存在，属于我方的填充物）：

| 被砍的内容 | 为什么不成立 |
|---|---|
| 「加载完成」 | 启动前根本没有"加载"这回事，是编出来的状态。假的比空的更糟。 |
| 「准备就绪」/「就绪」（v1 出现 3 次） | 这是**常态**。常态不该占版面。只在异常时说话。 |
| 「Java 21」 | 属于版本设置。玩家不因为 Java 21 而决定启动；出问题时才来看。 |
| 「内存 8 GB」 | 同上，且玩家不会在这里改。 |
| 「15 个版本」 | 回答的是"总共有几个"，而首屏问的是"启动哪个"。属于版本列表页。 |
| 「24 个模组」 | 弱相关。标题里的 Fabric 已经说明"这是个重实例"，数字是装饰。 |
| 版本 chip + 大标题重复 | 同一事实说了两遍，其中一遍是死重量。 |

**留下的（全屏一共 5 个元素）：**

| 元素 | 它改变哪个决定 |
|---|---|
| 版本名 + 加载器（大标题） | 决定"这局玩什么"——是不是我想玩的那个档 |
| 上次游玩时间（kicker） | 决定"要不要换个档"——很久没碰的实例往往不是今天想玩的 |
| 启动按钮 | 唯一的行动 |
| 版本 / 设置（次要入口） | 需要换档或改配置时才用 |
| 账户（顶栏小 chip） | 确认"是我在玩"，切换时才点 |

### 状态显示规则

| 状态 | 首屏表现 |
|---|---|
| 一切正常 | **什么都不显示**（不写"就绪"） |
| 缺 Java / 需补全文件 / 上次启动崩溃 | 在 kicker 位置替换成一句具体的话 + 一个修复入口，颜色用 warn/danger |
| 启动中 | 主按钮转红「取消启动」+ 按钮内底部 2px 进度线 + kicker 换成当前阶段（"正在准备运行环境"） |
| 运行中 | 主按钮变深色「游戏中 · 点击结束」，kicker 换成运行时长 |

## 2. 为什么不是卡片网格（保留 v1 结论）

第 3 轮把「版本 / 账户 / 运行环境 / 启动进度 / 快捷操作」摊成 5 张等权卡片：
视觉重量被切成五份，眼睛没有落点；开发时"每个功能一个卡"最省事，但首屏变成了仪表盘。
启动器首屏不是仪表盘，是**一个决定 + 一个按钮**。

红线：首屏的容器型视觉元素（有底色 / 边框 / 圆角的块）**不超过 1 个**（即主按钮）。

## 3. 方案 D · 全幅（推荐）

一张 16:9 横图铺满内容区，文字与按钮压在左下角。

### 1375 × 897

| 元素 | 数值 |
|---|---|
| 窗口圆角 | 12 |
| 侧栏 | 208 宽，右侧 1px `#14171d` |
| 内容区 | 1167 × 897 |
| 背景图 | cover，`center 44%`；不加任何模糊 |
| 遮罩 | 下：`rgba(5,8,14)` .94→.62→.06→0（0/20/52/70%）；左：.72→.18→0（0/38/62%）；上：.62→.10→0（0/20/40%） |
| 顶栏 | 高 52，右内边距 104（让出窗口按钮），账户 chip 右对齐 |
| 文字块 | 左 64 / 右 64 / 底 58 |
| kicker | 11.5px，字距 .1em，距下 15，前 22×1px 品牌蓝 |
| 标题 | 58px / 行高 1.02 / 字距 -.022em；加载器段用 `#9fb4cf` |
| 操作行 | 距上 34；主按钮 高 48 / 左右 34 / 圆角 10；ghost 高 34 / 圆角 8 |

### 800 × 550

| 元素 | 数值 |
|---|---|
| 侧栏 | 64，仅图标 |
| 内边距 | 左 28 / 右 24 |
| 顶栏 | 高 46，右内边距 96 |
| 标题 | 34 / 行高 1.06 |
| 操作行 | 距上 20；主按钮 高 42 / 左右 22 |

## 6. 背景图实现约束

1. 图源优先级：当前版本 splash/背景 → 用户自定义背景 → 内置图。**禁止**用纯色顶替。
2. `Image { fillMode: Image.PreserveAspectCrop }`，不用 `Stretch`（像素画拉伸会糊）。
3. 遮罩用 2~3 个 `Rectangle + LinearGradient` 叠加，**禁止**整窗 `layer.enabled` / `MultiEffect`（本项目出现过纹理重分配导致文字放大、控件消失）。
4. **禁止** `backdrop-filter` / 毛玻璃压图（QML 无原生实现，需离屏模糊，成本与风险都高）。压在图上的一律用不透明深色或半透明纯色。
5. 不用 `SpringAnimation`（已证实数值发散到 -Infinity）。

## 7. 审美验收 rubric（100 分，≥80 且无 0 分项才算过）

| # | 项 | 分 | 判定方式 |
|---|---|---|---|
| 1 | 焦点唯一 | 10 | 眯眼看截图，第一眼只有一处 → 主按钮 |
| 2 | 无冗余信息 | 12 | 指着每个可见元素问"它改变哪个决定"，答不出就 0 分 |
| 3 | 空白性质 | 10 | 每处空白都能说出"为什么空"（呼吸 / 衬托图 / 分隔） |
| 4 | 层级可辨 | 10 | 前/中/背三档能一一指出 |
| 5 | 字阶跨度 | 8 | 最大/次大字号比 ≥1.5 |
| 6 | 色彩克制 | 8 | 强调色出现 ≤2 处 |
| 7 | 对齐一致性 | 8 | 同列元素共享一条左边线（用标尺量） |
| 8 | 边界关系 | 8 | 元素到窗口边的距离只用 3 种值 |
| 9 | 图像质量 | 8 | 有真实画面填充，非纯色/图标放大 |
| 10 | 主操作唯一 | 6 | 页面只有 1 个实心主按钮 |
| 11 | 状态真实 | 5 | 无占位头像、无编造状态词、无假数字 |
| 12 | 小窗适配 | 7 | 800×550 与 1375×897 是同一套构图 |

**打分只能由看图的一方打，执行端不得自评通过。**

## 8. 迭代纪律

1. **禁止重置**：在现有 `qml-next` 上改，不删旧实现。
2. 每轮只修 rubric 最差的 3 项，并写明改了哪 3 项。
3. 每轮出两张截图（1375×897 + 800×550）与上一轮并排对比。
4. 交付写"待评审"，不得写"完成"。
