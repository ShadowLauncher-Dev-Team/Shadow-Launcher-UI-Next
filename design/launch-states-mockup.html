Java 缺失自动补全 LaunchBackend 的 java 节点；installJavaForLaunch() + 安装器轮询 只在「检查 Java 环境」节点的子行显示 正在下载 Java 21 (37%)...，11px 灰蓝小字 会显示，但和普通检查文字混在一起，看不出"这是在替你补 Java"
authlib-injector.jar 缺失自动下载 deps 节点内下载，成功/失败都有信号 下载中同样只有子行小字；下载失败只发 launchCheckWarning，新 UI 没有任何监听 下载中勉强可见；失败完全静默，用户以为外置登录可用
崩溃分析 CrashDetector::analyzeCrash() 后台线程：crash-reports / hs_err / latest.log / debug.log，51 条规则、疑似模组、建议、导出 zip 新 UI 没有崩溃弹窗，只有浮层节点转红 + 「查看日志」。旧 UI 有 qml/CrashDialog.qml 不会弹窗。分析结果算了但没人显示
多开 / 强制结束 / 进程监控 runningGames()、runningCount、killGameByPid()、killGameProcess()、退出 detach / 重启 adopt 新 UI 完全没有界面；旧 UI 在 MainWindow 里有「运行中 (n)」列表 + KillButton 能力齐备但无入口。另外"运行时长"后端没有字段，需要补 startedAt

另有两个后端缺口，选哪套方案都要补：① 预检失败（如 Java 缺失）只发 crashDetected，成功/失败两种"启动失败"路径发的是不同信号，新 UI 要统一；② 进程启动后 3 秒内死掉的路径只发 launchCheckFailed + toast，不做崩溃分析，这条最容易漏。
