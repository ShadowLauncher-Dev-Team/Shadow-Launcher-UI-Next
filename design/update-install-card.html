更新卡片设计稿 v3 · 卡片指的是「安装窗口」

你的判断成立：下载是启动器内的静默后台行为，安装发生在独立进程 SLUpdater，那里已经有自己的小窗口 —— 卡片要打磨的是它。
代码事实（update/SLUpdater.cpp）：
· 启动器内：checkSilent 发现新版 → 后台静默下载到 _update/（无任何 UI）；下完只发一条 toast「更新已就绪，点击立即重启安装」。
· 用户点重启 → quitForUpdate() 起新进程，PreInit 见 state.json=Ready → 拉起 SLUpdater（独立 exe，纯 Win32 无 Qt），旧进程退出。
· SLUpdater 现在已经有一个 420×150 深色窗口：标题「正在准备更新…」20px、阶段文字 15px、进度条（marquee / 真实百分比）。阶段文案是真实存在的六段：
　正在等待旧版本退出… → 正在更新文件… 5% → 正在清理旧文件… 92% → 正在替换主程序… 95% → 正在清理更新缓存… 98% → 更新完成，正在启动… 100%
· 最后一步 确实会自动重启新版本 —— 所以参考图那句「更新完成后将自动重启应用」放到这个窗口上是对的；放到启动器内那个"就绪提示"上才是错的（那里必须用户点）。

实现代价（提前说清）：SLUpdater 是纯 Win32 无 Qt 进程，要做无边框圆角卡得改窗口样式：WS_POPUP + SetLayeredWindowAttributes（或 DwmSetWindowAttribute 圆角）+ 自绘进度条（现在用的是 PROGRESS_CLASS 系统控件）。工作量集中在一个 createProgressWindow 里，不影响安装逻辑。
启动器内那侧就不再做任何下载卡片：静默下载 + 完成后一条「已就绪，点击重启」提示，保持现状；要不要改成倒计时自动重启，等你定。
