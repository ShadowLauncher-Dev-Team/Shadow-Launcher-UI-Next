## 三、三个方案

### A「版本优先」——最接近现有 MC 版本页
顶部一行四组分段：版本 → 类型 → 架构 → 系统；下面一张 72 高推荐卡（结构照 `latestCard`：11px 眉标 + 22px 主标题 + 右侧 CTA）；再下面是文件列表（48 高行，右端「下载」）；最后一张「本机已检测到 4 个 Java」信息卡。
- 优点：与 MC 版本页零学习成本；用户要什么点什么。
- 缺点：默认要选 4 个维度才看到文件；第一次用的人不知道"我该装哪个"。

### B「检测优先」（推荐）
第一张卡直接回答"我缺什么"：本机 3 已就绪 + 1 待补齐，右侧一个「一键补齐（1 个）」；下面三行是启动器真正需要的运行时（Java 8 / 17 / 21，对应 `installRequiredJavas` 的计划），已装显示版本号、缺失显示大小并给「下载并安装」；最后一条折叠「手动选择版本 / 类型 / 架构」，展开就是 A 的内容。
- 优点：多数用户只需要"补齐缺的那个"；把 Adoptium 的 msi/zip/架构这些概念藏到进阶区。
- 缺点：比 A 多一层"自动检测"，需要页面加载时调一次 `scanSystemJavas()`（后端已有）。

### C「控制台式」
左 200 筛选树（版本 25/17/11/8，当前 17 展开 JDK/JRE × x64）+ 右侧密集表（文件名/类型/大小/更新时间/操作）。
- 优点：信息密度最高，多版本对比最方便，和资源库 C 版同一语言。
- 缺点：左右两栏挤压，1100 宽下文件名只能显示到 17.0.…；与下载页其他 tab（单列列表）风格割裂。

## 四、推荐 B，理由

1. 这是**给启动器自己用的 Java 页**，不是通用下载站：用户要的是"能玩"，不是"选一个 exe"。
2. 现有后端已经有 `scanSystemJavas` + `installRequiredJavas`（8/17/25 JDK 串行安装、跳过已装、单任务互斥），B 是唯一能把这套能力直接露出来的布局。
3. 手动下载（A/C 的能力）在 B 里以折叠区保留，不丢功能。
4. A、C 的"多维度选择"在这个场景收益很低：架构基本永远是 x64，系统永远是 Windows。

## 五、无论选哪个，都要先补的后端能力（第 3 步一起做）

1. 单版本"下载并安装"：下载 → 解压到 `java_cache/{major}`（剥顶层目录）→ `verifyJavaMajor` + `isJavaComplete` 校验 → 失败清理。复用 `installJavaAsync` 最省事。
2. 真取消（现在 `cancelDownload()` 只 `deleteLater`，网络请求还活着）。
3. 已安装列表 + 删除某个缓存 Java（B 的 chips 需要"哪个是我装的"这个信息）。
4. 页面上"已就绪/缺失"需要 `scanSystemJavas()` 在进入 tab 时触发一次（当前只在设置页/安装时扫）。

# D 版：交互式「逐级抵近」（按旧 UI 思路重做，外观用新 UI 语言）

配套：`d1-step1.html/png`（第 1 步）· `d3-mid.html/png`（第 3 步，中段）· `d2-step5.html/png`（第 5 步，终点）

## 旧 UI 的思路（`qml/JavaPage.qml`，只取思路不取外观）

- 五个**级联**步骤：① 选 Java 版本 → ② JRE/JDK → ③ CPU 架构 → ④ 操作系统 → ⑤ 安装形式；
- 上一步没选，下一步是禁用的；每步都带一句科普 hint（JRE vs JDK、x64/x86、MSI vs ZIP）；
- 拉列表时有 spinner + "正在拉取版本列表……"；
- 最后一步出现文件卡（名称 / 体积 / 扩展名徽标 / 下载箭头，hover 放大 1.03），点卡弹保存目录，卡片下方出现进度条。

## D 版怎么"抵近"

同一个决策链，但改成**一层层向里走**的观感，而不是五个下拉排成一列：

1. 顶部一条**步骤轨**（①→⑤）：已选的节点变实心蓝、当前节点蓝框微光、没到的灰；连线走过就亮。
2. 每次只有**一张"当前步骤"的大卡**展开，选项是**横排胶囊**（不是下拉），下面跟着那一步的 hint —— hint 保留，因为它确实省掉一次搜索。
3. 选完 → 这张卡**收拢成 rail 上的值**，同时在下方留一颗小 chip（带 ×，点回那一步重选）；下一步的卡**原地展开**，眼睛不用来回跳。
4. 走到第 5 步：一条"已选 Java 17 · JDK · x64 · Windows"摘要在上，下面两张文件卡（ZIP / MSI，各带一句用途说明）。
5. 点下载 → **卡片原地变成进度条**（底部 2px 蓝条 + 62% · 18.4 MB/s + 约剩 8 秒），不跳页面、不弹窗。

## 与旧 UI 的差异（需确认）

| | 旧 UI | D 版 |
|---|---|---|
| 控件 | 5 个下拉 | 横排胶囊（点击成本更低，选项本来就只有 2–5 个） |
| 步骤呈现 | 全部平铺、逐个启用 | 只有当前步展开，已选收成 chip / rail 值 |
| 架构 / 系统 | 必须手动选 | **按 `cpuArch` 预选**（x64 / Windows），可改 |
| 下载反馈 | 卡片下方单独一条进度条 | 进度长在卡片里 |
| hint | 每步都有 | 保留，但只在当前步显示 |

其中"架构 / 系统自动预选"是行为变化：后端只能给 CPU 架构，系统恒为 Windows 时可判定，所以 D 预选了；如果你要求严格照旧 UI（强制用户走完 5 步），我改回不预选。

## 建议

- 若你认同"抵近"这个方向，D 比 A/B/C 更适合"新旧通吃"：流程是老的，观感是新的；对第一次用的人也比 5 个下拉友好。
- 实现上逐步卡片正好对应 `selectedVersion → selectedType → selectedArch → selectedOS → javaFiles` 这四级联动，QML 里就是一个 `step` 整数 + 4 个条件渲染块，比 A 的四组分段更好写。

## D 版已确认的两个细节（2026-11-07）

### 1. MSI 走「保存文件」，不弹目录选择

| | ZIP（便携版 Portable） | MSI（安装版 Installer） |
|---|---|---|
| 启动器做什么 | 下载 → 解压到 `<exeDir>/java_cache/{major}`（剥顶层）→ 校验 → 自动出现在 Java 列表 | **只下载**，不执行 |
| 落盘位置 | `java_cache/{major}` | 系统「下载」目录（`QStandardPaths::DownloadLocation`），默认不弹框；卡片右侧留「另存为」 |
| 为什么 | 便携包，启动器能自己管 | .msi 要 UAC 提权、写 Program Files / 注册表 / PATH / JAVA_HOME，属于修改用户系统，启动器不代劳 |
| 装完谁认 | `scanSystemJavas` 扫 `java_cache/*` | 同一函数扫 `Program Files\Eclipse Adoptium` 等常见目录 |

文案随之分开（不再对 MSI 说"自动加入列表"）：

- ZIP：`便携版（Portable）· 解压后由启动器托管，不写注册表`
- MSI：`安装版（Installer）· 写入系统目录与 PATH / JAVA_HOME，需管理员权限`

### 2. 进度只在 Java 页本页，不进「下载进度」页

理由：

1. 「下载进度」是**批量资源下载**的聚合页；Java 只有 1 个文件，属于单件操作，混进去会稀释那张页面的语义；
2. Java 的链路是 **下载 → 解压 → 校验 → 登记**，后三步只有 Java 页有语境（哪个主版本、装到哪、为什么失败）；
3. 沿用既有教训：一处操作只在一处显示进度（两处进度必然打架）。

切走后仍要看得见：**Java tab 上带一个小进度指示**（下载中＝细环，完成＝绿点随即消失），点回 tab 就在卡片里看实时进度。启动流程里的 Java 自动安装属于「启动浮层」的节点，不在这个页面，两者互不干扰。

> 实现提示：ZIP 的"下载并安装"接到 `JavaRuntimeInstaller::installJavaAsync`（已有 下载→解压→校验 全链路 + `downloadProgressChanged`）；MSI 走 `JavaBackend::downloadJavaFileTo` 只下载。
