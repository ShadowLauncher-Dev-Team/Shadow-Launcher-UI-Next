# 版本设置页 · 后端接口调研

日期：2026-11-08 ｜ 目标：ui-next 的「版本设置」全页（收起侧栏）
代码：`src/backend/settings_backend.{h,cpp}`、`version_backend.{h,cpp}`、`check_backend.h`、`src/core/version_isolation.*`

## 0. 结论先说

- **每个版本能覆盖的 11 项，后端接口已经全都有了**（`SettingsBackend` 的 `versionXxxMode/versionXxx` 系列）。
- **都是即改即存**（QSettings 写入 + `sync()`），**没有事务、没有撤销**。所以 UI 不能给「保存/取消」，只能给「自动保存 + 单项恢复全局」。
- **缺**：按版本的分辨率、版本图标、显示名；也**没有**一个「这版覆盖了哪几项」的汇总接口（要逐项查 11 次）。设计稿据此标注：分辨率标成「全局设置」，不给覆盖开关。

## 1. 每版本覆盖（全部 `Q_INVOKABLE`）

| 设置项 | 读 | 写 | 语义 |
|---|---|---|---|
| Java | `versionJavaMode(id)` | `setVersionJavaMode(id,int)` | 0 = 跟随全局；其余为 `availableJavaList()` 的索引 |
| 内存 | `versionMemoryMode(id)` / `versionMemoryManualMB(id)` | 同名 setter | mode 0 = 跟随全局；manualMB 缺省 2048 |
| JVM 参数 | `versionJvmArgsMode` / `versionJvmArgs` | 同名 setter | mode 0 = 跟随全局 |
| 游戏参数 | `versionGameArgsMode` / `versionGameArgs` | 同名 setter | 同上 |
| 强制独显 | `versionHighPerfGpuMode` / `versionHighPerfGpu` | 同名 setter | mode 0 = 跟随全局 |
| GC | `versionGcMode` | `setVersionGcMode` | 0 = 跟随全局，1..3 = 覆盖 |
| 自动进服 | `versionAutoJoinServer` | `setVersionAutoJoinServer` | 空串 = 跟随全局 |
| 全屏 | `versionFullscreenMode` / `versionFullscreen` | 同名 setter | mode 0 = 跟随全局 |
| 窗口标题 | `versionWindowTitleMode` / `versionWindowTitle` | 同名 setter | mode 0 = 跟随全局 |
| 启动前命令 | `versionPreLaunchMode` / `versionPreLaunchCommand` | 同名 setter | mode 0 = 跟随全局 |
| 退出后命令 | `versionPostExitMode` / `versionPostExitCommand` | 同名 setter | mode 0 = 跟随全局 |

存储：QSettings，键形如 `versionMemory/<versionId>/mode`、`versionJava/<versionId>/index`（见 `settings_backend.cpp:535+`）。
**写进去就生效**，没有"草稿"概念——这决定了三版设计稿都只在顶部放一个「改动自动保存」的状态字，不放假按钮。

## 2. 全局默认值（同一文件，属性形式）

`javaPath / javaVersion / javaMajor`、`minMemoryMB / maxMemoryMB / autoMemoryEnabled`、`isolationEnabled`、
`gcMode`、`fullscreenEnabled`、`autoJoinServer`、`windowTitleOverride`、
`preLaunchCommand / postExitCommand`、`windowWidth / windowHeight`、`processPriority`。

「跟随全局」显示的就是这些值，所以每一行都需要能读到全局值才能显示"跟随全局 · Temurin 17.0.9"这种文案。

| 动作 | 接口 | 备注 |
|---|---|---|

| 打开目录 | `openVersionDir(id)` / `openGameDir()` | |
| 重命名 | `VersionBackend::renameVersion(old,new)` | 改的是版本 id，不是显示名 |
| 克隆 | `VersionBackend::cloneVersion(src,new)` | |
| 复制路径 | `copyVersionPath(id)` | |

## 4. 辅助

- `CheckBackend::checkMemory(maxMemoryMB)` → `QVariantMap`：内存建议/超限提示（设计稿里「自动建议 4096 MB」用它）。
- `SettingsBackend::availableJavaList()` / `findJavaForVersion(requiredMajor, maxMajor)`：Java 下拉的数据源与"这版需要哪个大版本"。

## 5. 缺口（要补后端才能做，设计稿已经避开）

1. **按版本的分辨率不存在**：只有全局 `windowWidth/Height`；per-version 只有全屏。→ 三版设计稿把分辨率标成「全局设置」，不做覆盖开关。
2. **版本图标 / 显示名没暴露**：`renameVersion` 改的是 id。→ 设计稿不放"改名/换图标"，只放「重命名」（明确是改 id）。
3. **没有事务**：无法"改了再取消"。→ 顶部只显示「改动自动保存」。
4. **没有汇总接口**：判断"这版覆盖了几项"要逐项查 11 次。→ 建议后端补 `versionSettingsSummary(versionId)`，否则 QML 每次进页面 11 次跨语言调用 + 11 个 QSettings 读。
5. 环境变量、代理、自动更新等参数后端未暴露 → 设计稿不含。

## 6. 三版概念稿与接口的对应

- **A 左栏分类 + 单列表单**：左 5 组（运行时/窗口/参数/自动化/文件），右每行 = label + 控件 + 继承开关；开关直接映射 `mode`（0/1），红点计数用第 4 条汇总接口。
- **B 卡片墙**：6 张卡 = 6 组，卡头显示「覆盖 N 项」，行内不重复标注（字最少，代价是精确到"哪一项"要进卡看）。
- **C 启动配方控制台**：左折叠组 + 右只读合成预览（`java -Xmx4096M …`），把"11 组控件"的解释压力交给预览区，控件区因此可以更安静。

三版都遵守：**不使用 emoji / 不用图标代替文字**；颜色全部取自 `ui/Theme.qml` 的 token。
