# 联机页 · C++ 后端调研（2026-11-07）

> 目的：为新 UI（`ui/`，`--ui-next`）的「联机」页做设计前的事实核对。
> 结论先行：**后端已经是一套完整的「房间 + 局域网桥」实现**（对标 Terracotta），
> 旧 UI `qml/MultiplayerPage.qml` 是它的完整参考实现；新 UI 目前**只有侧栏入口，没有页面**。

## 2. 状态机（`MultiplayerManager::State`，Q_ENUM）

| 值 | 枚举 | 后端 stateText（原文） | 角色 |
|---|---|---|---|
| 0 | Idle | （空） | — |
| 1 | CreatingRoom | 正在创建房间... | 房主 |
| 2 | JoiningNetwork | 正在加入联机网络... | 访客 |
| 3 | Discovering | 正在查找联机中心... | 访客 |
| 4 | Connecting | 正在连接到 ip:port | 访客 |
| 5 | Connected | 已连接 / 已加入房间 | 访客 |
| 6 | WaitingForGuests | 等待玩家加入... / 在线 | 房主 |
| 7 | WaitingForMcServer | **请打开游戏，进入单人世界后按 「Esc → 对局域网开放」** | 房主 |
| 8 | VerifyingConnection | 正在验证MC连接... | 访客 |
| 9 | Error | 具体错误 | — |

**角色**：`Role { None, Host, Guest }`。**上限 5 人（含房主）**：`kMaxPlayers = 5`，满员时 `errorOccurred("房间已满（5/5）")`。

## 4. 真实交互流程（照抄后端，非设计想象）

**房主**
1. `createRoom()` → 生成房间码 → `CreatingRoom`
2. 起 easytier（`JoiningNetwork` 语义）→ 起 Scaffolding 服务端 → `WaitingForGuests`
3. **MC 未开服**时进入 `WaitingForMcServer`，文案直接给操作指引（Esc → 对局域网开放）
4. `mc_scanner` 扫到本机 MC 的广播 → 拿到真实端口 → 广播给访客 → `Connected`
5. 之后每 5s 健康检查，连续 3 次失败 → `errorOccurred("MC服务器连接已断开，联机会话结束")`；**2 分钟**内没开服 → `errorOccurred("MC服务器启动超时，联机会话结束")`
6. 最后一名访客离开 → 回到 `WaitingForGuests`（"等待玩家加入..."）；**5 分钟**无人 → `errorOccurred("房间已空闲超时，自动关闭")`

**访客**
1. `joinRoom(code)` → 校验码（失败："房间码无效，请检查后重试"）→ 起隧道 → `Discovering`（找不到中心："未找到联机中心，请确认房主已创建房间"）
2. → `Connecting` → 指纹校验（最多 20 次重试）→ 拿服务端端口
3. → `VerifyingConnection`（0xFE 握手，最多 8 次；**8 次不过也放行**，与 Terracotta 一致）
4. → `Connected`（"已加入房间"）→ 起 FakeServer，在自己机器上伪造一个局域网世界，MC 的「多人游戏」里直接能看见
5. 房主 15s 无数据 → `handleHostLost("房主已离开，房间已自动退出")` → 回 Idle

**限流**（要写进 UI 提示）：进房失败 3 次 → 冷却 **60 秒**；同 IP 每分钟最多 6 次进房、20 次连接。

## 5. 设计必须遵守的约束（来自实现，不可自由发挥）

1. **没有「踢人 / 房主转让 / 聊天 / 密码房」**——后端没有对应接口，设计稿里不能出现。
2. **玩家信息只有**：名字、vendor、延迟、HOST/GUEST。没有皮肤、没有头像帧同步；头像由 `playerHeadPath` 从本地账号目录取（可能不存在）。
3. **房间码是唯一分享物**：`copyRoomCode()` 只写剪贴板，没有二维码/链接（如需二维码=新增能力，要单独立项）。
4. **进度是「阶段」不是百分比**：只有 `state`，没有 0-100 的下载式进度。进度条只能是 indeterminate 或按阶段步进。
5. **错误只走 toast**：`errorOccurred(msg)` → 旧 UI 用 toast + 页面抖动。设计稿里错误态要能承接「一次性文案 + 已回 Idle」。
6. **合规声明**（旧 UI 页面底部原文，需保留）：
   > 使用联机服务，即表示您承诺，在多人联机全过程中，您将严格遵守您所在国家或地区的全部法律法规。您不得将多人联机功能用于除多人联机外的其他用途。
7. 昵称可改（`setPlayerName`），默认取账号名，离线账号另算，兜底 "Steve"。

## 6. 需要覆盖的页面状态（设计稿验收清单）

1. 空闲（未建房）：创建 / 加入两个入口 + 昵称
2. 创建中（房主）
3. 加入中（访客，正在起隧道）
4. 查找中心 / 连接中心（访客）
5. **等待 MC 开服**（房主，最关键的一个中间态，带操作指引 + 2 分钟倒计时）
6. 房间在线（房主视角，含空位）
7. 验证 MC 连接（访客）
8. 房间在线（访客视角）
9. 错误（房间码无效 / 房间已满 / 未找到中心 / 连接断开）
10. 房主离开（访客被踢回，含提示）
