# 联机页 · 成员身份模型（结论稿）

> 起因：影指出「顶栏显示用户名，但联机用的身份跟用户名毫无关系，是这台设备的」。
> 这是对的。下面是代码事实、可选方案、推荐结论。

---

## 1. 代码事实（全部来自 `src/multiplayer/multiplayer_manager.cpp`）

联机时在网络上被识别的字段只有四个：

| 字段 | 来源 | 说明 |
|---|---|---|
| `machine_id` | 本机生成的设备 ID | **真正的主键**，同账号换机器 = 另一个人 |
| `name` | 客户端自报的显示名 | 默认取启动器账号用户名；未登录兜底 **"Steve"**（:33） |
| `hostname` | `QSysInfo::machineHostName()`（:1304） | 电脑名 |
| `vendor` | 固定 `"shadow"`（:1305） | 哪家启动器 |

关键点：

1. **`name` 只是"你让我怎么叫你"**，不参与任何鉴权、不绑定账号。改了只是改这块牌子（`setPlayerName` :310–313 只改本地变量 + emit）。
2. **心跳每 5 秒带一次 `name`**（:1302），所以名字是"随设备上报"的。
3. **头像完全不代表身份**：`playerHeadPath(name, dataDir)` 只是用 `MD5("OfflinePlayer:"+name)` 的奇偶位决定用 `steve_head.png` 还是 `alex_head.png`（:2030–2047）——两张默认皮肤头，谁看都一样。
4. **联动缺陷（需补）**：房主侧收到老玩家心跳时只更新 `latency`（:1251–1258），**不更新 `name`**。也就是说"在房间里改昵称"，别人那边不会立刻变。这条要么补后端，要么设计上写明"改名后重新加入才生效"。

---

## 2. 候选方案

### A. 不显示名字，只显示设备码
`A3F1 · 38ms`。最准确，但 5 个人全是乱码，朋友之间没法叫名字。**不采用**。

### B. 直接用电脑名（hostname）
`DESKTOP-8FJ2K` / `Linsanity-PC`。不用设置、天然唯一，但：
- 中文用户常是 `DESKTOP-XXXX`，不可读；
- 电脑名常含真实姓名/公司名，等于默认泄露；
- 想改要动系统设置，太重。
**不采用**（但可作为兜底/副信息）。

### C. 设备昵称 + 设备码（推荐）
- 首次进联机页**自动生成**：取 hostname；取不到或太丑则 `玩机者 ` + 设备码。
- 可改，存在本机设置里（跟着设备走，换账号不变）。
- 列表显示：**昵称**（主）+ **4 位设备码**（副，小字，用于区分同名设备）。
- **不显示 MC 账号名**；账号名与联机身份解耦。

---

## 3. 推荐结论

**用 C。而且不需要用户提前设置**——首次自动生成一个能用的名字，想改再改。

理由：
1. 用户第一次点「创建房间」时不该被一个设置表单拦住；
2. 名字是社交属性，不是技术属性，机器无法自动算准；
3. 设备码兜底保证了"两个人都叫 影的电脑"也能分辨；
4. 与 MC 账号解耦后，未登录用户开联机也不会出现 "Steve" 这种鬼名字。

---

## 4. 落地要动的四处

1. `MultiplayerManager`：新增 `deviceName` 属性 + 持久化（settings 文件），首次取 hostname；`setPlayerName` 改为写它。
2. 心跳带上的 `name` 用 `deviceName`，**不再**用账号名（`shadow_backend.cpp:2183–2191` 那段 account→setPlayerName 的联动要拿掉或改成只做初始值）。
3. 房主侧心跳处理补一句"名字变了就更新 `name`"（:1251 那段）。
4. UI：联机页顶栏 chip 从"账号名"改成"设备昵称 + 设备码"；成员列表用昵称 + 设备码 + 延迟。
